# Card art pipeline

Card and token art is **not** generated by the project. Every card uses the placeholder (a game-icons silhouette on a Path-tinted
gradient) until real images are added here. When you say **"import card art"**, run `bash tools/import_art.sh` and report what was
added and what is still missing.

## The frame

Cards are 2:3 (laid out at 300x450, `CardView.SIZE`). The art fills the whole card inside the frame border:

| Look | Where | What shows |
|------|-------|------------|
| FULL | hand, zoom, rewards, vendors, deck builder grid | name + cost bar on top; a semi-transparent type line and rules panel over the bottom third; rarity and attack/defense plaque |
| COMPACT | the battlefield | the art cropped to its upper-middle (middle 80% of the width, from 4% down), name bar and keyword chips |
| square | small thumbnails (deck builder lists, pack reveal) | `CardArt.square(id)`: full width, from 8% down |

Draw the subject in the **upper-middle**: the top bar and the bottom third are covered by text in the FULL look, and COMPACT crops the
edges.

## Importing from the Google Drive "Approved" folder

`data/source/art_config.cfg` holds `source_dir` (`G:/My Drive/Card Game Art/Approved`; override with env `ART_SOURCE_DIR`). `bash tools/import_art.sh` reads that folder **read-only**: it only copies (converted to WebP), never moves, renames or deletes anything there, and refuses a folder named "Pending Review" or "Superseded". Accepted: .png .jpg .jpeg .webp named exactly by Card ID or Token ID; other images are listed as unknown and skipped, non-images are ignored. One image is in memory at a time. Images that are not 2:3 are centre-cropped (never stretched) and listed as "Cropped". `data/source/art_import_manifest.csv` records each file's MD5, so when the Drive file for an ID changes the next import replaces the game art (listed as "Replaced"); unchanged files are skipped. `bash tools/shot.sh res://scenes/dev/art_review.tscn <name> --view=hand|zoom|compact|deck --chunk=N` shows the review sample (every Path, the longest names, every legendary) at each view's real scale.

## Adding art by hand

1. Export each image (PNG or JPG, any size; 2:3 is best, other ratios are centre-cropped) named by **Card ID** (`C-01.png`, `GRB-04.jpg`);
   tokens by **Token ID** (`T-01.png`). Put them in `_art_inbox/` (git-ignored).
2. If the files have other names, list them in `data/source/art_map.csv` (`filename,Card ID`) instead of renaming.
3. `bash tools/import_art.sh`. For each file it: crops to 2:3, resizes to **768x1152**, saves **WebP (quality 85)** to
   `assets/art/cards/<ID>.webp`, and moves the original to `_art_source/` (git-ignored; keep it as the master).
4. Read the printed summary (added, unknown file names, errors) and `docs/art/art_status.md` (every Card ID and Token ID, its name, and
   whether art exists). Commit `assets/art/cards/*.webp` and the status file.

Re-running with an empty inbox is a no-op that refreshes the status file. To replace art, drop a new file with the same name.

## Loading

`CardArt` (`ui/card/card_art.gd`) loads `res://assets/art/cards/<ID>.webp` by convention and caches it; a missing file returns
`null` and `CardView` draws the placeholder. Nothing else needs to be edited when art is added.

## Tests

`tests/core/data/test_card_art.gd`: the importer (naming, token and JPG input, art map, unknown names, re-import, status report, 2:3 crop),
the fallback and the square/compact crops. The fixtures are flat colour images made in `user://`, not card art.
